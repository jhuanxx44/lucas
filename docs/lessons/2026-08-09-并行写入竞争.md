# 并行工具调用不能全量并发：写入工具必须串行

## 问题

2026-08-02 引入并行工具调用时，同批所有 `function_call`（含写入）一律用
`asyncio.gather` 并发执行。真实任务里模型会在同一轮发出多个 `apply_patch`/
`write_file`（例如对同一文件的不同位置做多处修改），并发写会竞争同一文件状态，
结果不确定；对同一文件「读改写」的并发更是直接产生脏写。

## 修正

`ToolSpec` 增加 `parallelizable` 标记（默认 False = 串行，fail-safe）。Runner 执行
同一批调用时：

1. 标记 `parallelizable=True` 的只读调用（`read_file`/`list_files`/`search`/
   `wiki_recall`/`web_search`/`stock_quote`/`stock_kline`）用 `asyncio.gather`
   并发执行；
2. 未标记的写入调用（`write_file`/`apply_patch`/`update_plan`）在只读调用之后按
   模型发出顺序逐个 `await` 串行执行；
3. 两类结果按原调用顺序合并，`function_call_output` 仍整批一起回传（Responses
   协议不变）。

未知工具默认串行。

## 判断要点

- 并行是执行语义，必须由代码保证（`ToolSpec.parallelizable` + Runner 分流），不能只写进
  prompt 让模型自觉。
- 字段名用「可并行」而不是「是否写入」：属性是「能否安全地与同批其他调用并发执行」，
  默认不可并行；只读查询标记 True，改文件、改任务级状态（plan）等不标记。
