# 把模型的"思考过程"变成可展示的 thought 流

## 这次做了什么

聊天时，Lucas 现在会在动手之前先把"思考过程"逐字流式展示在 Trace 面板里（灰色斜体），最终答案单独展示。就像 Codex 那样：执行中能看到它在想什么，结论单独成段。核心改动只有一条——接住 DeepSeek 原生返回的 `reasoning_content` 字段，之前它被当噪音丢掉了。

## 1. 两种分离"思考"和"动作"的思路

要做出"过程 + 结论"的展示，前提是能把模型输出的**思考文字**和**动作/答案**分开。有两条路：

- **API 原生结构化通道**：模型 API 直接把思考放在一个独立字段里返回，和答案分属不同字段。你不用解析，API 已经替你分好类了。
- **纯文本里约定分隔符**：让模型输出一整段文本，中间用一个标记（如 `<<<ACTION>>>`）把"思考段"和"动作段"切开，自己写解析器按标记切。

调研 Codex 源码发现，它走的是第一条：OpenAI Responses API 原生返回带 `type` 标签的结构化项（reasoning / function_call / message），Codex 只是 `match` 这些已经分好类的项。它没有任何分隔符解析逻辑。

我们本来以为 Lucas 只能走第二条（纯文本分隔符），因为 Lucas 是多 provider + 自定义 JSON 文本协议，拿不到 OpenAI 那种原生 reasoning items。但实测发现——**DeepSeek 也有同款能力**：`deepseek-v4-flash` 会把思维链放在独立的 `reasoning_content` 字段，和答案 `content` 分离，流式下各有各的 delta。所以我们也能走第一条，而且比分隔符更稳。

## 2. 为什么原生字段比分隔符好

分隔符方案有几个脆弱点：模型可能忘写标记、思考文本里可能自然出现那个标记、切分逻辑要处理跨 chunk 边界。这些都是"靠模型自觉 + 自己写解析"带来的风险。

原生 `reasoning_content` 把这些风险全免了：分类是 API 在协议层做的，不依赖模型记得写什么标记，思考和答案物理上就是两个字段，不会串味。代价是绑定了 DeepSeek 的字段语义——但这次的方向本来就是专为 DeepSeek 优化，可以接受。Gemini 等其他 provider 没有这个字段，就退化成"只有答案、没有思考"，不影响它们正常工作。

## 3. 关键设计判断：思考通道独立于动作协议

Lucas 的动作协议是"模型每轮吐一个 JSON（`{"action":"tool"...}` 或 `{"action":"answer"...}`），代码解析后执行"。这次**完全没动这套协议**。

原因是：思考（`reasoning_content`）和答案（`content`）在 API 层就是两个独立的流。所以只需要：

- `reasoning` 段 → 逐段发 `thought` 事件，展示为过程；
- `content` 段 → 照旧累积成 JSON、喂给现有解析器提取答案、并作为"原始输出"进入下一轮历史。

**关键一点：思考不进"原始输出"。** 多轮对话时，喂给下一轮的历史只包含 `content`（那个 JSON），不含思考文字。这保证了动作解析和历史回放与改动前一字不差——思考纯粹是"给人看的旁白"，不参与 agent 的状态。

```
模型流 ──┬─ reasoning delta ──→ thought 事件 ──→ 前端过程区（灰色斜体，结束折叠）
         └─ content delta ────→ JSON 累积 ──┬─→ 解析器提取 reply ──→ 答案区
                                            └─→ 进入下一轮历史（不含思考）
```

这就是"思考通道独立于动作协议"：加一条只读的旁路，不碰主干。改动因此很小，风险也低。

## 4. 为什么不需要动流式解析器

Lucas 有个 `AnswerStreamParser`，负责从流式 JSON 里边收边提取 `reply` 字符串（要处理 `\n`、`\"`、`\uXXXX` 跨 chunk 边界）。一开始担心加思考要重写它。

结论是不用。因为 `reasoning_content` 是**纯文本**、和 `content` **物理分离**——它不在那个 JSON 里，直接原样透传即可，没有转义、没有结构。解析器只处理 `content` 段，逻辑完全不变。这再次说明"原生分离"省掉了多少麻烦：如果走分隔符方案，思考和 JSON 混在一段文本里，解析器就得同时应付两种格式了。

## 小结

- 想做"过程 + 结论"的展示，先确认你的模型 API 有没有**原生的独立思考字段**。有就用它，比自己在文本里切分隔符稳得多。
- DeepSeek 的 `reasoning_content` 就是这样的字段，且默认开启、逐字流式，不用调任何参数。
- 把思考做成"独立于动作协议的只读旁路"，不进历史回放，是让改动保持最小、不影响 agent 行为的关键。
