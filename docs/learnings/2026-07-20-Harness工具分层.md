# Harness 工具分层：注册能力不等于授予权限

## 为什么要分层

原来的 `harness/tools/` 把工具协议、工作区通用工具和 Lucas 投研工具放在同一层，`business.py` 又同时包含联网搜索、股票行情和 Wiki 召回。代码不算多，但文件路径无法表达依赖和测试边界。

现在保留 `base.py` 和 `registry.py` 作为 Harness 基础设施，把具体工具分成两组：

- `generic/`：文件系统、本地文本搜索、公共互联网搜索。
- `business/`：股票行情和 Lucas Wiki 等投研领域工具。

`AgentRunner` 与 `ToolRuntime` 不依赖任何具体工具；产品聊天和 Eval adapter 在装配阶段选择所需的 `ToolSpec`。

## 关键决策

工具是否注册与本次运行是否获准使用是两件事：

- 注册决定 runtime 是否知道如何执行一个工具。
- `allowed_tools` 决定当前产品请求或 Eval task 能否调用它。

Eval adapter 可以注册完整工具集合，便于不同 task 复用同一个 runtime，但不能再把业务工具无条件并入 task 白名单。这样 task manifest 才是权限的唯一事实来源，工具选择 Eval 也不会被隐藏的默认授权干扰。

## 取舍

本次只做路径和权限边界整理，没有为每个工具创建 class 或额外抽象。`stock_quote` 与 `stock_kline` 继续放在同一个模块，因为它们共享股票代码校验和行情 provider；`web_search` 不含投研领域语义，因此归入通用工具。
