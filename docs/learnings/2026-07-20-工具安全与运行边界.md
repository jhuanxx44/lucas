# 工具安全与运行边界：检查最终目标，而不是输入字符串

## 路径安全

阻止 `../` 和绝对路径只能防住字符串形式的越界，无法阻止工作区内 symlink 指向外部文件。安全判断必须发生在解析 symlink 之后：先得到 workspace 与目标的真实路径，再确认目标仍是 workspace 的子路径。

递归工具还有额外风险。`list_files` 和 `search` 不只访问用户传入的入口路径，还会产生新的 child/candidate，因此每个候选都要重新检查。当前策略选择跳过所有递归遇到的 symlink，既防目录逃逸，也避免 symlink 环和重复遍历；显式 `read_file` 仍可读取最终目标位于 workspace 内的链接。

Wiki 同样遵循两层边界：先确认 `workspace/wiki` 本身没有链接到外部，再确认索引页和全文 fallback 的每个页面都位于真实 Wiki 根目录内。路径安全由 `utils/path_safety.py` 的单一 helper 保证，filesystem 与 Wiki 不再各自实现近似规则。

## Deadline

只在 step 之间检查时间不能构成超时保证：当前模型请求或工具 handler 如果挂起，代码永远到不了下一次检查。Runner 现在从 run 开始计算一个绝对 deadline，并用剩余时间包住每次模型和工具 await；超时会取消当前协程、记录 `timeout` trace，并返回 `finish_reason=timeout`。

## Observation 预算

工具自己的截断不足以保护 Agent 上下文，因为联网搜索和未来工具可能返回任意长度。Runner 因此增加统一的单次与全 run observation 字符预算：注入 history、trace 和 SSE 的都是受限文本，并显式标记截断。最终答案仍优先于预算检查，模型拿到最后一次受限 observation 后可以正常完成作答。

## 注册与授权

工具注册表示 runtime 知道如何执行；`allowed_tools` 才表示本次运行获得授权。产品聊天使用 `lucas.yaml` 白名单与已注册聊天工具的交集，Eval 使用 task manifest 白名单，二者都不再暗中补充权限。
