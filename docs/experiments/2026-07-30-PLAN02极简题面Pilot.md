## 实验问题

把 PLAN-02 instruction 缩减为一句开放目标：

> 使用 sources/2026Q3/ 中三家半导体公司的正式季度材料，把知识库更新到 2026Q3，并发布一份可追溯的横向比较结果。

其他 fixture、grader、工具、system prompt、模型和预算不变。观察模型是否会因为任务开放而主动
调用 `update_plan`，以及它会怎样解释“更新知识库”“可追溯”和“发布比较结果”。

这是一项意图理解 probe，不是可直接进入正式 suite 的公平 outcome eval：原 grader 仍要求固定
报告路径、索引链接、公司页来源和风险保留，其中部分要求不再由极简题面明确公开。

## Trace 摘要

Agent 的实际路径是：

```text
列 sources
→ 读取三份季度简报
→ 列 wiki 并读取 index
→ 读取三个公司档案
→ 覆盖写入三个公司档案
→ answer
```

它没有调用 `update_plan`，没有创建任何横向比较报告，也没有更新 `wiki/index.md`。最终 summary
却声称“三家公司档案已更新至2026Q3，索引已同步，Q3横向对比完成”，最终回答也列出了一个
实际上不存在的 `wiki/reports/电子/2026Q3半导体横向对比.md`。

公司页的季度事实和原风险提示被保留，但没有写入来源路径。原 grader 因此三项均失败：来源缺失、
固定报告不存在、索引链接不存在。

## 结论

1. 极简开放目标没有提高 Planner 触发率，`update_plan` 仍为 0。
2. 模型能自行发现 sources、公司页和 index，说明基本环境探索能力存在。
3. 模型把“横向比较结果”放进最终回答，却把“发布”错误地自报为已经写入文件；这是候选答案没有
   outcome validation 的直接失败案例。
4. 当前 Optional Planner 路由没有把“多个文件 + 新报告 + 索引 + 可追溯”识别为需要计划的任务。
5. 极简题面不适合作为最终 benchmark，因为固定路径等要求变成隐藏标准；它适合作为开放目标理解
   与无依据完成声明的 capability probe。
