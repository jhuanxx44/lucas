# 评估 Harness 新增 Suite 批量运行支持

## 这是什么

之前评估一次只能跑一个 task，现在可以一次跑一组——就像一个"考试套卷"，批量执行、统一汇总，让你一眼看到整个 Agent 在所有题目上的表现。

## 要解决什么问题

写 Agent 最难的不是让它答对一道题，而是改了 A 功能，B 题挂了。如果每次改完代码都得手动 `run 这个 task`、`run 那个 task`，烦且容易漏。

Suite 解决的痛点是：**把一组 task 组织成一个套件，一键运行，统一看分**。相当于 CI 里的 test suite 概念搬到 Agent 评估上。

## 核心设计

### 1. Suite 文件定义（suite.yaml）

用 YAML 声明式定义套件，不改代码：

```yaml
id: smoke-v1
version: 1
tasks:
  - READ-01
  - EDIT-01
```

三个字段：名称、版本、任务列表。够用、不罗嗦。

### 2. 加载时严格校验（load_suite）

加载 suite 不是"读了就行"，而是**当场把所有坑检查出来**：

- 有没有不认识的字段？（防止拼写错误）
- 有没有缺少必填字段？
- task 列表是不是空的？
- task 有没有重复？（防止写了两遍自己不知道）
- 声明的 task 目录存不存在？

这些检查在加载阶段就报错，不会跑到一半才发现 `READ-01` 不存在——**早发现、早修、不用等**。

### 3. run_suite 的串行模型

```python
for task_id in suite.tasks:       # 遍历每个 task
    for trial in range(trials):   # 每个 task 跑 N 次
        result = await run_trial(...)
```

两层循环：外层串行跑不同 task，内层跑 N 次 trial（消除随机性）。**选择了简单串行**，因为现阶段 task 数量少（<10 个），串行的清晰度比并行复杂度的收益更值得。

### 4. Agent 适配器模式

不同 Agent（Oracle 占位符、Lucas Single）通过适配器统一接口：

```python
def build_adapter(name: str, task: TaskSpec) -> AgentAdapter:
    if name == "oracle":
        return OracleAgent(task.reference_dir)
    if name == "lucas-single":
        return LucasSingleAgent()
```

后续加新 Agent 类型，只加一个适配器注册，不动运行逻辑。

### 5. 汇总输出

跑完后产出一个 `summary.json`，包含：

- 总跑多少次、过了多少、成功率
- 按 task 分组：每个 task 的通过率
- 逐条 run 详情：finish_reason、各 grader 维度得分

一页纸看清全局 + 钻到单条排查。

## 取舍

- **串行没用并行**：当前 task 少，并行省不了多少时间反而引入状态干扰和排查复杂度。
- **CLI 用子命令不用配置文件**：`eval-harness run-suite smoke --trials 3` 够用，不引入配置文件管理的复杂度。
- **Suite 和单个 run 共目录**：一个 suite 的多次 run 都放同一个 suite 目录下，方便整体打包复制、压缩归档。

## 一句话总结

Suite 就是评估版的"一键跑全量回归测试"。声明一个 task 列表，校验通过后串行跑完，输出汇总结果——让改完代码后的验证从"手工逐个跑"变成"一条命令看全局"。
