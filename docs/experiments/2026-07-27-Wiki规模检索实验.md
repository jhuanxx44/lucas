# Wiki 规模化构建与检索实验

日期：2026-07-27；统一简体后 Agent 复跑：2026-07-28  
状态：已完成

## 1. 结论先行

本实验不支持直接将生产召回从子串 BM25 切换到 TF-IDF。

- 使用 OpenCC `t2s` 将 500 篇派生 Wiki 页面统一为简体后，固定 LLM 预分词关键词、共享 jieba 表示的 500 页结果由 TF-IDF 显著领先翻转为 BM25 数值领先：Recall@5 为 0.922 vs 0.936，TF-IDF − BM25 为 -0.015，按 query 聚类的 95% CI 为 `[-0.088, +0.044]`。差异不显著。
- 归一化前的 0.951 vs 0.855 主要由繁简错配驱动，不能作为公式优劣证据。归一化后，朴素子串 TF-IDF 在 500 页的 Recall@5 为 0.809，仍低于生产子串 BM25 的 0.873。
- 统一简体并修正 TF-IDF 查询/文档 tokenizer 一致性后，完整重跑 54 个真实 Agent trial：生产子串 BM25 与 jieba TF-IDF 均为 27/27 成功，事实和证据覆盖均为 100%，错误证据率为 0%。当前 3 个 task 出现天花板效应，无法区分质量。
- 成功率打平时，生产子串 BM25 的平均工具调用、tokens、成本和延迟均更低：1.11 vs 1.30 次、7,465 vs 8,745 tokens、`$0.0208` vs `$0.0243`、7.19s vs 8.77s。

当前决策：保留生产子串 BM25。统一文字表示后，纯公式对照不再显示 TF-IDF 优势，Agent outcome 完全打平而 BM25 更省。现有 3 个任务转为回归候选；下一轮要增加能避免天花板效应的困难多证据任务，不能继续用这 3 题判断排序质量。

## 2. 机制假设

验证三个假设：

1. 只增加非相关/弱相关干扰文档时，TF-IDF 与 BM25 的排序差异会随规模系统变化。
2. 知识库增大不仅改变离线排名，也会降低 Agent 最终事实和证据覆盖。
3. 离线指标优势只有稳定传导到 Agent outcome，才足以支持生产切换。

主要离线指标为 Recall@5/10、MRR、NDCG@5/10；Agent 主要指标为确定性事实覆盖、证据路径覆盖和最终成功率。辅助记录 steps、工具调用、tokens、成本和延迟。

## 3. 冻结母库

### 3.1 来源与构建

- 500 篇唯一 Wiki 页面，501 个真实网页快照。
- 通过 Firecrawl 抓取网页，LLM 只对当前快照做去噪、摘要和结构化。
- 目标/近邻/远端分层为 150/200/150，覆盖 16 个领域。
- 抓取、重复或整理失败的页面从已策展真实候选池替换；失败记录保留为 rejection ledger。
- 最终 source plan：`source-plan-500-frozen.jsonl`。
- 编译后的 500 篇派生页面通过 `scripts/convert_to_simplified.py` 使用 OpenCC `t2s` 统一为简体；不修改 `raw/`、来源快照和稳定文档路径。转换到固定点后二次扫描为 0 篇待转换。

来源真实性达到目标，但权威性与多样性仍有限：扩展页以中文维基百科这一二级来源为主，一级来源比例不高。这里的“中高质量”指结构、可追溯性、去重和抽检质量达标，不能解释为每篇都有多家一级来源交叉验证。

## 4. 查询与可见规模控制

- 基于冻结页面生成 60 条查询，拆分为 20 dev / 40 test。
- 使用与生产 Agent 相同的 DeepSeek 配置生成并冻结 2–8 个 LLM 预分词关键词；模型为 `deepseek-v4-flash`，keyword prompt SHA-256 为 `3e2e4a6fe80a63d8b2ce32217f6d53b417abad6fe7d8b8cf6ada7d9cdb6a0818`。离线 runner 会拒绝只有自然语言问句、缺少关键词缓存的查询。
- 覆盖公司事实、概念、跨文档、近邻干扰、长尾、同义词和证据不足。
- TF-IDF 与 BM25 各取 Top-20，再加入同领域与稳定随机文档构成候选池，由 LLM 标注 0–3 级相关性。
- 全集含 50 条可回答、10 条证据不足查询；test 集有 34 条可回答查询。
- 受控轨道为每条查询保留全部 grade≥2 ground truth，只增加分层干扰文档。
- 自然增长轨道允许相关证据随规模进入；5 个 seed 是分层的模拟入库顺序，不代表真实网页发布时间顺序。
- 生成 1,220 个 manifest：受控 1,200 个，自然增长 20 个。所有 manifest 均通过 hash、数量、GT 包含和 50⊂100⊂200⊂500 嵌套校验。

## 5. 离线结果

### 5.1 纯打分公式对照

输入是冻结的 LLM 预分词关键词，不使用已淘汰的自然语言问句路径。纯公式对照再让这些关键词与文档共享 jieba tokenizer；两种算法共享查询 token、候选文档和正分过滤，只替换公式。test 集每个规模为 34 条可回答 query × 5 seeds。

| 规模 | TF-IDF R@5 | BM25 R@5 | 差值 [95% CI] | TF-IDF NDCG@10 | BM25 NDCG@10 |
|---:|---:|---:|---:|---:|---:|
| 50 | 0.986 | 0.979 | +0.007 [+0.000, +0.021] | 0.979 | 0.983 |
| 100 | 0.978 | 0.971 | +0.007 [-0.006, +0.022] | 0.968 | 0.969 |
| 200 | 0.962 | 0.953 | +0.008 [-0.016, +0.038] | 0.957 | 0.946 |
| 500 | 0.922 | 0.936 | -0.015 [-0.088, +0.044] | 0.920 | 0.928 |

统一简体后，各规模均未出现 TF-IDF 的显著优势；500 页时 BM25 数值领先。归一化前 500 页的差距集中在 5 条 query，其中 3 条涉及“南亚科技”：查询关键词为简体“南亚”，正确页面正文为繁体“南亞”，TF-IDF 靠残存普通词的向量集中度偶然提高正确页排名。归一化后这 3 条全部打平，500 页只剩 QS-003 为 BM25 胜、QS-059 为 TF-IDF 胜，其余 32 条可回答 query 打平。

TF-IDF 的索引构建更慢：500 页平均 37.6ms vs BM25 17.2ms；查询更快：3.2ms vs 7.9ms。这里测的是当前 Python 实现，不是生产容量基准。

自然增长轨道的 R@5 从 50 页的 0.127/0.127 上升到 500 页的 0.922/0.936，主要因为相关页面逐步进入可见集合，不能据此单独归因排序公式。

## 7. 机制决策

1. 保留生产子串 BM25，不切换朴素子串 TF-IDF。
2. 撤回“共享表示下 TF-IDF 在 500 页稳定领先”的结论；它主要是繁简错配造成的评测伪差异。
3. TF-IDF 候选若继续实验，查询与文档必须共享 tokenizer；对应回归测试保留，禁止复合关键词直接匹配 jieba token。
4. 当前 3 个任务在所有条件稳定通过，可作为 regression 候选，但不再承担算法区分任务。
5. capability suite 下一轮增加困难多证据、同名实体、同义词和 Top-5 边界任务，再比较质量；成功率继续打平时，以成本、延迟和实现可靠性选择生产方案。

## 8. 局限

- 60 条查询由 LLM 基于现有页面生成，虽经过候选池重标注，仍可能偏向页面措辞。
- 相关性标注不是完整人工全库判定，Top-20 pooling 之外仍可能漏标。
- Agent 只选 3 个 task、每条件 3 次，统计功效有限；统一简体后全部成功，存在明显天花板效应。
- 语料扩展页主要来自单一百科来源，不能代表企业内部 Wiki 的格式和来源分布。
- 500 页只能覆盖小型到中型范围，不能外推到数千或百万文档。
- OpenCC `t2s` 统一文字系统但不做台湾/大陆词汇本地化，例如“软体”“滑鼠”仍保留；后续若发现查询词汇变体，应作为独立 alias/同义词实验处理。
