# LLM 关键词 vs jieba 分词检索对照实验

**日期**：2026-07-26  
**状态**：已完成  
**关联 commit**：`bdf8e17`

---

## 1. 实验目标

围绕 `wiki_recall` 的生产链路，回答一个问题：**用 LLM 提取中文关键词再检索，是否优于 tool 内部 jieba 分词？**

在上一轮 BM25 对照实验中发现：查询集的 `keywords` 字段（人工编写的实体名和专业术语）检索效果远好于自然语言输入（TF-IDF 从 R@5=0.650 跳到 0.882）。但这批 keywords 是人工精心挑选的，不能代表真实 LLM 行为。

本实验用真实 LLM（DeepSeek-Chat）对每条自然语言 query 实时提取关键词，对比生产链路中 jieba 分词和 LLM 分词的真实差距。

---

## 2. 实验设计

### 变量

| 路径 | 输入 | 检索引擎 | 关键词来源 |
|------|------|:--------:|------------|
| NL（jieba） | 自然语言问题 | BM25 | `extract_keywords()` — jieba 分词 + 词性过滤 |
| KW（LLM） | 自然语言问题 | BM25 | LLM 实时提取 → 空格拼接 → tool 直接分词 |

两组共用同一 BM25 索引和 46 篇 wiki 文档，唯一变量是**谁来做分词**。

### LLM 关键词提取

- **模型**：`deepseek-chat`
- **System Prompt**：提取实体名、专业术语、领域关键词；排除疑问词和语义词；3-8 个关键词空格分隔输出
- **回退**：LLM 调用失败时回退到 jieba（本次实验 0 次回退）

### 查询集与评估

沿用上一轮 BM25 实验的 15 条查询 + 46 篇 wiki fixture + 确定性 grader（R@5 / P@5 / MRR / NDCG@5），确保数字可比。

### 对照基线

| 基线 | 说明 |
|------|------|
| 人工 KW + BM25 | queries.json 中手动编写的 keywords，用作理论上限 |
| 人工 KW + TF-IDF | 同上但用 TF-IDF 检索引擎 |

## 3. 实验结果

```
Mode                                R@5      P@5      MRR   NDCG@5
----------------------------------------------------------------
NL (jieba → BM25)                0.4789   0.3333   0.7074   0.4958
KW (LLM → BM25)                  0.6911   0.4833   0.8667   0.6894
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
人工 KW + BM25  (参考上限)         0.7711   0.5200   0.9667   0.8075
人工 KW + TF-IDF (参考上限)        0.8822   0.6000   1.0000   0.9029
```

**LLM 关键词 vs jieba**：R@5 从 0.479 → 0.691（**+0.212**），四项指标全面提升。

**LLM 关键词 vs 人工上限**：R@5 差 0.08（0.691 vs 0.771），差距主要来自：
- 干扰查询 q13（消费品牌本地化）LLM 返回 0 结果——正确行为，语料库确实没有消费类文章
- q07（波分复用）LLM 丢了缩写 "WDM"
- 人工关键词包含更多领域同义词（如 q02 人工写了 "GPU/图形处理器/深度学习/并行计算"，LLM 也提取了这些但少了一两个）

### 按查询类型

| 查询类型 | jieba R@5 | LLM-KW R@5 | Δ |
|----------|:---------:|:----------:|:---:|
| 公司事实 (q01-q04) | 0.567 | 0.733 | +0.167 |
| 概念解释 (q05-q08) | 0.625 | 0.792 | +0.167 |
| 跨文档综合 (q09-q11) | 0.511 | 0.689 | +0.178 |
| 干扰查询 (q12-q15) | 0.208 | 0.500 | +0.292 |

干扰查询受益最大（+0.292）：LLM 提取的关键词如"电动汽车/续航里程/充电速度"不会像 jieba 那样切出"技术""突破"等通用词，避免了大量半导体文章被误召回。

## 4. LLM 关键词提取质量分析

### 典型优秀案例

**q01**（全球晶圆代工市场参与者）：
- jieba：`['全球', '代工', '市场', '参与者', '工艺水平', '竞争', '定位']`
- LLM：`['全球晶圆代工', '晶圆代工市场', '主要参与者', '工艺水平', '竞争定位', '台积电', '三星', '英特尔']`
- 差异：LLM 保留了 "全球晶圆代工" 作为完整术语，并直接点出了台积电/三星/英特尔这些实体名

**q09**（芯片从设计到成品的环节）：
- jieba：`['设计', '成品', '芯片', '经历', '核心', '环节']`
- LLM：`['芯片', '设计', '制造', '封装', '测试', '流片', '良率']`
- 差异：LLM 展开了"核心环节"的具体内容（制造/封装/测试/流片），检索精准度根本不在一个量级

### 典型不足

**q07**（波分复用技术）：
- LLM：`['波分复用技术', '光纤', '多路信号', '同时传输']` — 缺 "WDM" 缩写
- 人工：`['波分复用', 'WDM', '光纤', '多路信号']`
- 导致 LLM 只召回 7 篇，人工召回 12 篇

## 5. 结论与行动

### 核心结论

LLM 分词在实际生产链路中碾压 jieba（R@5 +0.212），且 DeepSeek-Chat 15 次调用零失败，无需回退机制。差距的根本原因不是 jieba 分词算法差，而是**自然语言到检索关键词这个语义鸿沟，只有 LLM 能填**：

- jieba 只能做字面分词，面对"全球晶圆代工市场有哪些主要参与者"无能为力
- LLM 能识别实体、展开概念、判断领域相关性，"读懂了问题再搜"

### 行动

1. **删除 NL 路径**（已完成，本实验后立即执行）：`wiki_core.py` 移除 `extract_keywords()` 和 `_STOP_WORDS`，`recall_wiki()` 的 `mode` 参数只保留关键词模式
2. LLM 关键词提取逻辑由 Agent 在调用 `wiki_recall` 前完成（prompt 中通过工具描述引导），不在 tool 内部做第二次 LLM 调用
3. 后续可在 Agent prompt 中加入关键词提取的示例，引导模型产出高质量检索关键词

### 局限

- 人工关键词仍然比 LLM 高 0.08 R@5，说明 prompt 引导还有优化空间
- 46 篇小语料的数字迁移性有限；扩库后的 LLM 分词表现需重新验证
- 本实验用的是 DeepSeek-Chat，如果生产用其他模型需重新对照
