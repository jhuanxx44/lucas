# BM25 检索排序对照实验

**日期**：2026-07-26  
**状态**：已完成  
**关联 commit**：`32e90a9`

---

## 1. 实验目标

在 46 篇简体中文维基百科文档（覆盖半导体、光通信 + 多行业干扰项）上，对比 TF-IDF 和 BM25 的检索质量。

## 2. 实验设计

### 知识库

| 指标 | 数值 |
|------|------|
| 文档数 | 46 篇 |
| 来源 | Firecrawl 抓取中文维基百科，仅保留正文 |
| 清洗 | 去链接/图片/infobox/导航模板/参考文献章节，简繁统一转简体 |
| 目录结构 | 按真实行业分类（半导体/光通信/汽车/新能源/消费电子/软件/互联网/食品饮料/餐饮/体育用品），无 "噪声" 标签泄露 |
| 总字符数 | ~430K，平均 ~9.4K 字符/篇 |

### 查询集

15 条自然语言查询，按类型分布：

| 类型 | 数量 | GT 规模 | 设计原则 |
|------|------|---------|----------|
| 公司事实 | 4 | 3-5 篇 | 词汇泛化（"代工市场" 替代 "晶圆代工企业"） |
| 概念解释 | 4 | 3-4 篇 | 功能描述替代术语（"多路信号同时传输" 替代 "波分复用"） |
| 跨文档综合 | 3 | 4-6 篇 | 产业链/技术演进拼接 |
| 干扰查询 | 4 | 1-4 篇 | 与目标域共享关键词但领域不同（"技术突破""全球扩张"） |

每条查询包含：
- 自然语言问题
- LLM 风格关键词（模拟 Agent 提取，含实体名和专业术语）
- 地面真相文档列表（GT）
- 设计理由（rationale）

### 评估指标

确定性 grader：`recall@k`、`precision@k`、`MRR`、`NDCG@k`（k=1,3,5,10）

### 检索引擎

| 算法 | 实现 |
|------|------|
| TF-IDF | jieba 分词 → TF-IDF 向量 → 余弦相似度 |
| BM25 | jieba 分词 → BM25（k1=1.5, b=0.75） |

两者使用相同的分词器（jieba + 停用词过滤）。

## 3. 实验结果

### 3.1 自然语言查询（完整句子输入）

| 指标 | TF-IDF | BM25 |
|------|:------:|:----:|
| recall@5 | **0.650** | 0.542 |
| precision@5 | **0.453** | 0.387 |
| MRR | **0.842** | 0.803 |
| NDCG@5 | **0.659** | 0.564 |

### 3.2 按查询类型

| 类型 | TF-IDF R@5 | BM25 R@5 |
|------|:----------:|:--------:|
| 公司事实 | 0.767 | 0.475 |
| 概念解释 | 0.708 | 0.688 |
| 跨文档综合 | 0.617 | 0.522 |
| 干扰查询 | 0.500 | 0.479 |

### 3.3 BM25 b 参数敏感性

| b | R@5 | P@5 | MRR | NDCG@5 |
|---|:---:|:---:|:---:|:------:|
| 0.00 | 0.531 | 0.333 | 0.752 | 0.510 |
| 0.25 | 0.492 | 0.347 | 0.817 | 0.534 |
| 0.50 | 0.514 | 0.360 | 0.793 | 0.542 |
| **0.75** | **0.542** | **0.387** | **0.803** | **0.563** |

默认 b=0.75 即为最优，降低文档长度惩罚反而损害性能。

## 4. 分析与结论

### 4.1 TF-IDF 在小语料上优于 BM25

46 篇文档的规模不足以让 BM25 发挥优势：
- **IDF 主导**：TF 饱和和长度归一化在极少文档时贡献微弱
- **长文是优势而非劣势**：内容最丰富的文档（华为 27K 字符）恰好信息量最大，惩罚它反而降召回
- **BM25 的舒适区在 200-500+ 篇**

### 4.2 干扰查询是共同短板

q13（消费品牌本地化策略）和 q14（体育用品技术创新）两条干扰查询两个算法都接近 0 分——自然语言里的 "品牌" "技术" "创新" 等词和半导体文档共享词汇，确定性 grader 无法区分 "关键词命中" 和 "实质相关"。这类查询需要 LLM grader 做主观判断。

### 4.3 后续方向

- 扩充知识库至 200-500 篇，预期 BM25 将反超 TF-IDF
- 启用 LLM grader 评估干扰查询的主观相关性
- 将 eval retriever 对接至改造后的 `wiki_recall` 工具，测试真实 Lucas 流程
